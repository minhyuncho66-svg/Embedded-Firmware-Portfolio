1. 목표
PI 제어로 목표 RPM(300)에 수렴하도록 모터 제어

2. 학습 내용
-> P 제어의 한계 / PWM = error × Kp
목표가 300RPM인데 실제 RPM이 올라갈수록 error가 작아지니까 PWM 보정량도 작아짐.
그래서 Kp=1.2에서는 약 178RPM에서 더 이상 못 올라가는 정상상태 오차가 발생.

-> I 제어 추가
error_sum += error; /PWM = error × Kp + error_sum × Ki;
I 제어는 오차가 계속 발생하면 그 오차를 누적해서 PWM을 추가로 올려주는 역할.
- Ki=0 → 약 178RPM
- Ki=0.01 → 약 229RPM
- Ki=0.03 → 약 300RPM 으로 출력값 상승 
왜 Ki=0.03이 맞았나
Ki가 클수록 누적된 오차가 PWM에 더 강하게 반영.
0.01에서는 보정이 부족했고 0.02, 0.03으로 올리면서 PWM이 더 충분히 증가해서 
300RPM 근처까지 올라간 것.

- P 제어는 현재 오차에만 반응해서 정상상태 오차가 생겼고, 
  I 제어는 오차를 누적해서 부족한 PWM을 계속 보충하기 때문에 목표 RPM까지 도달가능.

그 외 추가 개념
- error_sum을 전역변수로 선언해야 하는 이유: while문 안에 지역변수로 두면 
  매 루프마다 0으로 리셋되어 "누적"이 성립하지 않음
- pwm_adj를 0~999로 clamp하는 이유: PWM 레지스터(ARR=999)가 받을 수 있는 
  범위를 벗어난 값을 그대로 넣으면 안 되기 때문

3. 시행착오
- sprintf 포맷 지정자 오류: int16_t 타입인 count 변수를 %.0f(float용)로 
  출력->값이 이상하게 찍힘 → %d로 수정
- RPM이 "300대/30대"를 번갈아 튀는 이상현상: 처음엔 Integral Windup(적분 누적 폭주)를 
  의심해 error_sum에 clamp(-9990~9990)를 추가했으나 문제가 계속됨
- PWM 100% 고정 진단: PI 로직을 제거하고 듀티비를 999로 고정해서 
  이 모터의 실제 최고 RPM(약 1220)을 확인 → PI 제어 시 138 RPM에서 
  멈췄던 게 모터 스펙 문제가 아니라 제어 로직 문제였음을 확정
- Ki 과다로 인한 조기 clamp 도달: Ki=0.1일 때, RPM이 목표(300)의 
  절반도 안 된 상태(약 137)에서 이미 error_sum이 clamp 상한 근처까지 
  쌓여 pwm_adj가 999에 도달함 -> 과도한 반응(오버슈트) 발생 
  -> Ki를 0.1에서 0.03으로 낮춰서 해결 
(수치 조정은 Ai 조언을 참고했으나 왜 통하는지는 위 "학습 내용"에 정리한 대로 직접 검증하고 이해)

## 4. 배운 것
- 정상상태오차와 Integral Windup 등 PI 제어의 대표적인 문제를 
  실제 하드웨어에서 겪고 해결한 경험
- Ki 값의 크기가 수렴 속도와 안정성(오버슈트 여부)에 미치는 영향을 숫자로 직접 확인
