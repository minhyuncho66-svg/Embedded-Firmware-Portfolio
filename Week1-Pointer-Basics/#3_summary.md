#3 배열과 포인터의 연속성

### 오늘 배운 것
- 배열명(arr) 자체가 배열 첫 요소의 주소(&arr[0])와 정확히 같음
- *(ptr + i)로 대괄호 없이 배열 접근 가능
- 포인터 +1은 "1바이트"가 아니라 "타입 크기만큼" 이동
  (int32_t는 4바이트씩 이동, 실제로 628→62C→630... 확인함)
- ptr++ (순회)와 *(ptr+i) (상대접근)의 차이:
  - *(ptr+i): 원본 ptr은 고정, i만 바꿔가며 접근
  - ptr++: ptr 자체가 이동, 원래 시작 위치를 잃어버림

### 예측 vs 실제
- Q1: arr과 &arr[0]이 같을 거라 예측 → 실제로 완전히 같은 주소로 확인됨
- Q3: 포인터+1이 타입마다 다르게 이동할 거라 예측 → 
  int32_t는 정확히 4바이트씩 증가하는 것을 주소 출력으로 확인

### 오늘 겪은 시행착오
- int32_t 배열 만들 때 stdint.h 빠뜨림 → 추가해서 해결
- 포인터 선언할 때 별표(*) 빠뜨림 (int32_t ptr = arr; → int32_t* ptr = arr;)
- for문 조건 i<=5로 잘못 써서 배열 범위 넘을 뻔함 → i<5로 수정

### 오늘의 발견 (중요!)
- ptr++를 배열 크기만큼(5번) 반복하면 
  arr[5] 위치(배열 밖!)까지 가버림을 직접 확인
- 이게 "버퍼 오버플로우"라는 실무 버그의 기본 원리라는 것을 배움
- 그래서 실무에선 원본 포인터는 보존하고 
  순회용 복사본 포인터를 따로 쓰는 게 안전하다는 것 이해
