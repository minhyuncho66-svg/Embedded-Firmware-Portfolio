2\. 학습 내용

■블록 A: CTRL\_MEAS 레지스터 설정

\- osrs\_t = 001 (x1)

\- osrs\_p = 001 (x1)

\- mode   = 11  (Normal)

이 비트를 합친 0x27을 CTRL\_MEAS 레지스터 write -> 센서가 계속 측정시작

Normal vs Forced 모드 차이

\- Foced(01/11) ->이 값을 쓴다면 센서가 측정을 한번만 하고 끝난 이후 다시 sleep으로 돌아감 매번 값을 

&#x20;읽고 싶을때 사용

\- Normal(11) -> 센서가 자동으로 측정 - 대기 - 측정 - 대기를 반복 지속적으로 모니터링할때 사용



■블록 B: 보정계수(dig\_T1\~T3) 읽기

\*보정 계수를 왜 2바이트씩 묶어야 하는지

\-  1바이트 (8비트)로 표현할 수 있는 최대범위 정해져있음 -> 바이트 2개를 붙여 사용한다면 부호없이 0\~65535 /

&#x20;부호 존재할시 -32768 \~ 32767까지 가능 ex)dig\_T1값인 27504는 2바이트에서부터 사용가능

\*MSB/LSB 합치는 시프트 연산 (<<8 | )

\- 0x88 = dig\_T1 \[7:0] (lsb)

&#x20; 0x89 = dig\_T1 \[15:8] (msb) - 이 두바이트를 레지스터에서 읽어왔다 가정할시  다시 원래 숫자로 합치기 위해서 

&#x20; 먼저 MSB를 왼쪽으로 시프트해서 밀어주고 LSB랑 합치기 위해서 OR 연산 사용

\*unsigned vs signed 구분이 왜 중요한지

\- dig\_T2, dig\_T3는 signed short -  이 보정계수들이 음수값일 수도 있음 / 이걸 만약uint16\_t(부호 없음)으로 읽게   

&#x20; 된다면 큰 양수로 해석 // 타입 잘못 지정시 완전히 다른 결과 도출 

&#x20;그러므로 전역변수 선언시 int16\_t  dig\_T2; int16\_t  dig\_T3;로 선언

\*HAL\_I2C\_Mem\_Read 파라미터 구조 (DevAddress 8비트 시프트)

\- DevAddress = 슬레이브(센서)I2C주소  - 8비트 형식이므로 7비트 주소를 왼쪽으로 1비트 시프트해서 넣어야함



■블록 C: raw 온도값 20비트 재배치

MSB/LSB/XLSB 3바이트 → 왜 20비트만 유효한지

\- TEMP 레지스터는 0xFA(MSB), 0xFB(LSB), 0xFC(XLSB) 3바이트로 구성 각각 8비트 8비트 4비트로 

&#x20; 20비트 raw데이터 차례대로MSB부터 12비트 4비트씩 왼쪽으로 밀고 남은 XLSB에선 상위비트 (6,7,8,9)만 유효한 

&#x20;4개비트기때문에 오른쪽으로 시프트( >>4)



■블록 D: 보정함수 적용 + 스케일링

Bosch 공식 그대로 가져다 쓴 이유 (직접 유도 X)

\- Bosch가 부동소수점 없이 정수 연산만으로 근사치를 뽑아내려고 설계한 최적화 공식

리턴값 /100.0f 왜 필요한지 (정수나눗셈 vs float나눗셈)

\- 정수 나눗셈(int/int)은 소수점을 버리고 몫만 남기니까 5123/100은 51이 되고 뒤에 소수점이 다 날아가 버림.

&#x20;나누는 쪽(분모)이라도 100.0f처럼 실수형이면 C언어에선 자동으로 앞의 정수(T\_raw)도 

&#x20;float로 변환(암묵적 형변환)해서 5123.0f / 100.0f = 51.23f가 도출.
